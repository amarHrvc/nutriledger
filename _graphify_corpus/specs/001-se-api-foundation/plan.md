# Implementation Plan: SE API Foundation

**Branch**: `001-se-api-foundation` | **Date**: 2026-03-15 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/001-se-api-foundation/spec.md`

## Summary

Establish the foundational BE+FE infrastructure for the NutriLedger REST API pivot.
The BE delivers Sanctum token authentication, a structured `routes/api.php` with role-gated
route groups, a standardised `ApiResponses` trait, global error handling, and CORS
configuration. The FE delivers a bare-bones Vite + React SPA scaffold in `/frontend` with
an Axios client and a single smoke-test component that confirms CORS works from a real browser.

No domain CRUD (users, patients, visits) is built in this feature — those belong to 002, 003.

**Principle II — documented exception for auth endpoints:**
Constitution Principle II requires route middleware → FormRequest `authorize()` → Policy for
every request touching protected data. Auth endpoints (`/api/login`, `/api/logout`,
`/api/user`, `/api/ping`) do **not** access domain data (Patient, Visit). The full
three-layer stack therefore applies differently:

| Endpoint | Middleware | FormRequest authorize() | Policy |
|---|---|---|---|
| `GET /api/ping` | none (public) | n/a | n/a |
| `POST /api/login` | none (public) | returns `true` (public endpoint, no domain data) | n/a |
| `POST /api/logout` | `auth:sanctum` | n/a (no request body) | n/a (revokes own token) |
| `GET /api/user` | `auth:sanctum` | n/a (no request body) | n/a (returns own identity) |

Full three-layer enforcement applies to all domain endpoints in 002-patients and 003-visits.

## Phase 0: Research Findings

*See [research.md](research.md) for full detail.*

| Decision | Choice | Rationale |
|---|---|---|
| API versioning | Level 0 (none) | MVP with no external consumers; LARAVEL_API_RULES §4 says "start here" |
| Token abilities | Not used (roles via RoleMiddleware) | RoleMiddleware already JSON-aware; abilities add complexity without benefit for MVP |
| Response envelope | `{ message, status, data }` success / `{ message, errors }` 422 | Matches LARAVEL_API_RULES §2 exactly; don't invent a different format |
| CORS implementation | Laravel built-in `config/cors.php` | Zero additional dependencies; sufficient for dev + prod |
| React scaffold | `npm create vite@latest frontend -- --template react` | Official Vite scaffolding; JS not TS per constitution |
| Token expiry | 1 month (`Carbon::now()->addMonth()`) | LARAVEL_API_RULES §5 — always set expiry; 1 month reasonable for MVP |

## Phase 1: Design

*See [data-model.md](data-model.md) and [contracts/auth.md](contracts/auth.md) for full detail.*

### Key Design Decisions

**`ApiResponses` trait** lives in `app/Traits/ApiResponses.php`. All API controllers extend
`ApiController` which uses the trait. Direct `response()->json()` calls are forbidden in
controllers.

**`routes/api.php`** structure:
```php
// Public
Route::get('/ping', fn() => response()->json(['message' => 'ok', 'status' => 200, 'data' => ['status' => 'ok']]));
Route::post('/login', [AuthController::class, 'login']);

// Authenticated
Route::middleware('auth:sanctum')->group(function () {
    Route::post('/logout', [AuthController::class, 'logout']);
    Route::get('/user',    [AuthController::class, 'me']);

    // Role group skeletons (populated by 002, 003 features)
    Route::middleware('role:admin')->group(function () {
        // User management (002-users BE)
    });

    Route::middleware('role:admin,doktor')->group(function () {
        // Patients + Visits (002-patients, 003-visits BE)
    });
});
```

**Global exception handling** in `bootstrap/app.php` — intercept `AuthenticationException`
to return JSON 401 (not redirect), and `ValidationException` to return the standard 422
envelope. This ensures FR-005 and FR-007 hold even outside of controller code.

**React SPA** scaffold with Axios `baseURL` pointing to `VITE_API_URL`. Single `App.jsx`
that calls `GET /api/ping` on mount and renders the status in the DOM. No auth state —
that belongs to 002-users FE.
